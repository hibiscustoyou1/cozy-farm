# 田园经营小游戏 · 完整方案设计

> 定位：个人游玩项目 · 网页 H5 · 大屏 + 移动端自适应 · 无商业变现
> 前置调研见《田园经营游戏市场调研报告.md》
> v2 变更：技术栈加入 Vue3 + Pinia；时间系统改为"在线可调速 + 离线 1x"双模式

## 一、产品定位与设计原则

### 1.1 一句话概念

> **一座随身携带的小农场：想快就快、想慢就慢，每次打开都有作物在等你。**

### 1.2 因为"不变现"而成立的三个设计原则

参考治愈系游戏三要素（安全感 / 自主感 / 无失败），个人项目可以做得比商业产品更纯粹：

| 原则 | 具体落地 |
|---|---|
| **无失败** | 作物成熟后永不枯萎；不浇水只是"暂停生长"；换季不枯萎只下架种子 |
| **无压力** | 没有体力条、没有强制任务、没有限时活动、没有排行 |
| **有惊喜** | 关闭网页后时间继续流动（1x），每次打开都有"收菜惊喜"（离线结算） |

### 1.3 参考标杆

| 借鉴对象 | 借鉴什么 |
|---|---|
| 星露谷物语 | 季节轮换、昼夜流转的观赏性、作物图鉴 |
| Hay Day / QQ农场 | 真实时间生长 + 离线收益的核心节奏 |
| 桃源深处有人家 | 无 PVP 无排行的治愈定位 |

## 二、核心玩法循环

### 2.1 主循环

```
打开网页 → 离线结算面板（"你不在的时候…"）
   ↓
收获成熟的作物
   ↓
卖货赚钱 / 交给订单
   ↓
买新种子 / 开垦新地 / 买小鸡小牛
   ↓
种植 + 浇水 → 调整时间流速（想快就 10x，想挂机就 1x）
   ↺ 继续游玩 或 关闭网页（时间按 1x 继续）
```

### 2.2 时间系统（v2 重设计：双模式 + 可调速）

**核心概念：游戏时钟 gameTime**
- 所有游戏逻辑（作物生长、昼夜、季节、订单刷新）都基于 `gameTime`，**不再直接使用现实时间**
- `gameTime` 由游戏主循环推进：`gameTime += 现实delta × 速度倍率`
- 速度倍率玩家可调：**⏸ / 1x / 2x / 5x / 10x**

**两种模式**

| 模式 | 时间流速 | 场景 |
|---|---|---|
| **在线** | 玩家手动调速 0~10x | 沉浸游玩开 10x 看四季流转；挂机聊天开 1x |
| **离线** | 固定 1x，上限 8 现实小时 | 关网页后农场安静生长，回来有惊喜 |

> 设计本质：**速度选择器 = 在 Hay Day 模式和星露谷模式之间自由切换**。
> 防漏洞关键：离线永远 1x——否则"10x 种菜 + 关网页"等于无限加速。

**时间单位换算（1x 基准）**

| 单位 | 数值 | 说明 |
|---|---|---|
| 1 游戏日 | 24 现实分钟 | 含完整昼夜循环（日出 6:00 / 日落 18:00） |
| 1 季 | 7 游戏日 = 2.8 现实小时 | 换季换作物货架 + 场景色调 |
| 1 年 | 4 季 = 11.2 现实小时 | 10x 下 67 分钟跑完一年，观赏性拉满 |
| 订单刷新 | 每游戏日 3 单 | 1x 下每 24 分钟刷新，加速时更快（奖励沉浸） |

**速度选择器交互**
- 位置：桌面右上角常驻；移动端收进顶部状态栏（点开分段按钮）
- 桌面快捷键：`空格` 暂停/恢复，`1/2/3/4` 对应 1x/2x/5x/10x
- 视觉反馈：加速时太阳/月亮轨迹加快、时钟指针转动、云影流速变化
- 暂停时可正常操作农场（整理、种植、购买）——种下时记录当前 gameTime，恢复后才开始长

**浇水机制（宽松版，单位改为游戏时间）**
- 种下时需浇一次水启动生长
- 土壤湿度维持 24 游戏小时（= 1 游戏日），过期则生长**暂停**（不枯萎、不倒退）
- 10x 下湿度消耗也 10x——加速游玩时需要更勤浇水，这是速度的代价，形成节奏张力
- 雨天（P3 彩蛋）自动浇水

## 三、系统设计（按四期迭代）

### P0 · MVP：种植循环（先让它"好玩"）

**农场网格**
- 初始 5×4 = 20 格可耕种，周围留装饰性地块
- 扩地：金币解锁相邻地块（200 / 500 / 1200 / 3000…递增），上限 10×8 = 80 格
- 地块状态机：`荒地 → 耕地 → 已种植(生长中/成熟) → 收获后回到耕地`

**商店与经济**
- 种子商店（按当前季节过滤货架）
- 出售：背包一键卖出 / 单件卖出
- 等级：收获得经验，升级解锁作物与建筑

**存档**
- localStorage 自动存档（30 秒间隔 + 关页前 + 关键操作后）
- 支持导出/导入 JSON 文件（换设备 / 防手滑）

### P1 · 养殖 + 加工 + 订单

**养殖**（时长均以游戏时间计）

| 动物 | 建筑 | 购买价 | 饲料 | 产出 |
|---|---|---|---|---|
| 鸡 | 鸡舍 | 500 + 小鸡 200 | 小麦×1 / 2 游戏小时 | 蛋（3 游戏小时/枚，卖 40）|
| 奶牛 | 牛棚 | 2000 + 小牛 800 | 玉米×2 / 6 游戏小时 | 牛奶（6 游戏小时/瓶，卖 150）|

- 饲料可自动投放（勾选后从背包扣），断粮停产（不死亡）
- 动物有抚摸交互（爱心粒子 + 音效，纯情绪价值）

**加工建筑**

| 建筑 | 配方示例 |
|---|---|
| 厨房 | 蛋+小麦 → 蛋糕（材料 110 → 卖 200）|
| 作坊 | 牛奶 → 奶酪（150 → 280）；番茄 → 番茄酱 |
| 果酱台 | 南瓜 → 南瓜派（560+50 → 900）|

**订单板（目标感来源）**
- 每游戏日刷新 3 单，最多囤 6 单，可手动刷新 1 次
- 单子要求 2~3 种物品，奖励 = 物品售价 × 1.4 + 随机材料/装饰券
- 纯自愿，过期不惩罚

### P2 · NPC + 图鉴 + 钓鱼

**NPC（5 位，好感度系统）**
| NPC | 人设 | 喜好 |
|---|---|---|
| 村长 | 慈祥老爷爷 | 南瓜 |
| 杂货店老板娘 | 热心大姐 | 蛋糕 |
| 渔夫 | 沉默寡言 | 奶酪 |
| 木匠 | 傲娇少年 | 玉米 |
| 神秘旅人 | 季节限定出现 | 稀有作物 |

- 机制：对话（每游戏日首谈+好感）→ 送礼（喜好物 2 倍）→ 好感 1~10 级
- 好感解锁：专属剧情、装饰图纸、稀有种子
- **不做恋爱结婚**（内容量爆炸，个人项目慎入）

**图鉴收集**
- 作物 / 料理 / 鱼类 三本图鉴，收集率给称号（纯成就）
- 图鉴页显示未收集项的获取提示

**钓鱼小游戏（轻量版）**
- 池塘场景，点击抛竿 → 等待（随机 3~10 秒）→ "力度条"绿色区间点击收竿
- 鱼类 12 种，稀有度 3 档，图鉴联动

### P3 · 装饰 + 探索（长线内容）

**装饰系统**
- 商店购买：围栏、花坛、路灯、长椅、信箱、小池塘…（约 40 件）
- 自由摆放模式（网格吸附 + 旋转）
- 装饰券：订单与好感度产出，与作物经济隔离

**野外探索（轻量）**
- 农场外小地图（森林 + 河滩 + 山脚）
- 采集点：每 2 游戏日刷新浆果 / 蘑菇 / 芦苇
- 挖矿（可选，简化为"每日 3 镐头"）

### 4.2 关键技术决策

| 决策点 | 方案 | 理由 |
|---|---|---|
| 画布缩放 | Phaser `Scale.RESIZE` + 自定义布局管理器 | 真正利用不同屏幕，不留黑边 |
| 农场渲染 | 瓦片地图（Tilemap），相机可拖动/缩放（捏合）| 大屏看全局，小屏拖动浏览 |
| UI 层 | **Vue3 组件 + CSS 媒体查询** | 面板型 UI 天然响应式，比 Canvas UI 省力数倍 |
| 输入 | Pointer Events 统一处理 | 鼠标/触摸一套逻辑 |
| 触摸目标 | 交互元素 ≥ 44×44px | 移动端可用性底线 |
| 竖屏/横屏 | 均支持：竖屏时侧栏折叠为底部标签 | 不强制旋转 |
| 像素风渲染 | `pixelArt: true` + 整数倍缩放 | 避免像素模糊 |

### 4.3 交互细节

- **选中即预览**：点工具（锄头/种子/水壶）后，划过地块显示绿/红高亮
- **拖动批量**：按住拖动连续对多块地执行相同操作
- **长按 = 详情**：长按地块弹出信息卡（生长进度、剩余游戏时间）
- **收获反馈**：作物飞向背包动画 + 金币音效 + 轻微屏幕弹性
- **首次引导**：半透明高亮 + 三步提示（开垦 → 种植 → 浇水），可跳过
- **速度切换反馈**：切 10x 时昼夜快速流转的"延时摄影"观感，本身就是一个治愈时刻

### 5.2 混合架构分层（v2 核心变更）

```
┌─────────────────────────────────────────┐
│ Vue3 UI 层（DOM，低频更新）                │
│ · 面板：商店/背包/图鉴/订单/对话/设置       │
│ · 常驻：顶栏(金币/季节/时钟)、速度选择器、   │
│   移动端底部标签栏、Toast                  │
├────────────── Pinia ────────────────────┤
│ GameState（唯一真相源，可序列化 JSON）      │
│ · Vue 组件 reactive 订阅（低频字段）       │
│ · Phaser 场景每帧非响应式读取（高频字段）   │
├─────────────────────────────────────────┤
│ 系统层（纯 TS，不依赖 Vue/Phaser）         │
│ · TimeSystem（gameTime 推进/速度/离线结算）│
│ · GrowthSystem / EconomySystem /         │
│   OrderSystem / SaveSystem               │
├─────────────────────────────────────────┤
│ Phaser 表现层（Canvas，高频渲染）           │
│ · FarmScene：瓦片、作物、动物、动画、粒子   │
│ · 挂载在 Vue 组件的容器 div 中             │
└─────────────────────────────────────────┘
```

**三条铁律（防止混合架构的性能陷阱）：**

1. **高频数据不进 Vue 响应式**：作物生长进度、gameTime 这类每帧变化的值，Phaser 场景每帧直接从 store 原始对象读取（`markRaw` / `shallowRef`），绝不套 Vue Proxy——否则每帧触发依赖收集，性能雪崩
2. **Vue 只订阅低频结构化数据**：金币、背包数量、订单列表、好感度——只在变化时触发 UI 重渲染
3. **单向数据流**：UI 操作 → 调用系统层 action 修改 GameState → Phaser 订阅刷新画面；游戏事件（收获）→ 更新 GameState → Vue Toast 自动弹出

**Vue ↔ Phaser 集成要点：**
- Phaser 实例在 Vue `onMounted` 中创建，挂到 `<div ref="gameContainer">`
- 游戏实例用 `shallowRef` 持有（避免 Vue 代理 Phaser 整棵对象树）
- 通信走 Pinia：Phaser 不 import 任何 Vue 组件，Vue 不 import 任何 Phaser 类（仅类型）

### 5.4 时间系统与离线结算算法（v2 核心）

```ts
// —— TimeSystem：在线时由 Phaser update 驱动 ——
function tick(state: GameState, realDeltaMs: number) {
  state.gameTime += realDeltaMs * state.speed;  // 暂停时 speed=0
}

// —— 离线结算：读档时一次性推进 ——
function settleOffline(state: GameState, nowReal: number): OfflineReport {
  const OFFLINE_SPEED = 1;                          // 离线固定 1x
  const OFFLINE_CAP_MS = 8 * 3600 * 1000;           // 离线上限 8 现实小时（可配置）

  const realElapsed = Math.min(nowReal - state.lastSeen, OFFLINE_CAP_MS);
  const gameElapsed = realElapsed / REAL_MS_PER_GAME_MS; // 1 游戏毫秒 = 1 现实毫秒（1x 下）
  // 注：1 游戏日 = 24 现实分钟 → 1 游戏毫秒 = 1/60 现实毫秒？
  // 不 —— gameTime 单位即"游戏毫秒"，1x 下与现实 1:1 流动；
  // "1 游戏日 = 24 现实分钟"指的是游戏内时钟刻度（gameTime 的 24*3600*1000 = 1 游戏日）
  // 在 1x 速度下，跑完 1 游戏日需要 24 现实分钟。离线按 1x：gameElapsed = realElapsed。

  const before = state.gameTime;
  state.gameTime += realElapsed;                    // 1x：直接加
  return summarizeChanges(state, before);           // 成熟/产出/换季，生成结算报告
}

// —— 生长判定：全部基于 gameTime，与速度解耦 ——
function isMature(tile: Tile, crop: CropDef): boolean {
  // 有效生长 = 浇水窗口内的游戏时间
  return tile.wateredUntil - tile.plantedAt >= crop.growGameMs
      && state.gameTime >= tile.plantedAt + crop.growGameMs;
}
```

> 关键洞察：**速度倍率只影响 gameTime 的推进速率**，所有系统（生长/订单/昼夜/季节）只读 gameTime。这让"可调速"的实现成本几乎为零，且天然支持暂停。

**离线结算面板**：上线时弹 Vue Modal——"你离开的 2.5 小时里（游戏世界过去了 2.5 小时）：3 块玉米成熟了、母鸡下了 2 个蛋、杂货铺上新了 3 张订单"。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 范围蔓延（最大风险）| 严格按里程碑交付；P2/P3 每个系统可独立砍掉不伤主循环 |
| Vue/Phaser 混合架构性能陷阱 | 守住三条铁律：高频不进响应式、Vue 只订阅低频、单向数据流 |
| 加速玩法破坏数值平衡 | 长作物按游戏时长统一定价；10x 下浇水消耗也 10x，速度自带代价 |
| 离线结算边界 case（换季/断粮）| 结算算法纯函数化 + Vitest 单测覆盖 |
| 美术风格不统一 | 全套单一 asset pack，缺口用同风格作者补充 |
| 存档丢失 | 自动存 + localStorage 双写轮换 + 导出 JSON |
| 自己玩腻 | M2 后每期只加"自己最想要的功能"，兴趣驱动优先 |
